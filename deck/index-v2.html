SDD · 01  ·  live bake-off vs the rest

The spec is the guardrail..

SDD — spec-driven development: write the contract first. What it does, inputs, outputs, acceptance criteria. TDD — failing test second, encoding that contract as an executable check. AI writes the code; spec and test keep it honest. Why it matters with AI: models fill ambiguity with confident guesses and ship bugs in the same tone as working code — the spec removes the ambiguity, the failing test is the objective gate. Same prompt, three modes, three worktrees.

→ The prompt (identical for all three)

add reply-rate by hour of day to campaign analytics

Execute mode

Agent codes immediately. No plan, no spec.

What you get

A chart on the page. Looks right. Metric is silently wrong — numerator and denominator count different events.

134 lines · 0 tests · 18 min

Gain: fastest to something on screen.
Cost: slowest to correct. No test catches the bug. No reviewer catches it. Ships Monday, dies Wednesday.

Plan mode

Agent proposes a plan in chat. You approve, then it codes.

What you get

Happy path is correct. Timezone chain handled. Edge cases you didn't think to name fall back to defaults — and you'll never know.

426 lines · 2 tests · 6 min

Gain: right thinking, right shape, atomic commits.
Cost: the plan lives in your head, not on disk. The next agent (or future you) starts from zero.

SDD + superpowers

Brainstorm → spec → plan → failing tests → green. On disk.

What you get

A spec that names the bug from card 1 — in plain English — before any code runs. Edge cases enumerated. Commits link back to acceptance criteria.

779 lines · 10 tests · 8 min

Gain: a durable contract the next agent or human can ship against in 6 months.
Cost: 6× the artifact. Overkill if you're throwing it away.

The surprise: SDD ran faster than execute (8 min vs 18). Discipline isn't slower — execute pays its tax mid-flight, in debug loops. AI builds the code; we build the guardrails — spec, failing test, skill. The frameworks you'll see in a few slides (Superpowers, GSD, OpenSpec, Spec Kit) are four dialects of the same idea.

Orchestration · 04a  ·  two ways to parallelize

Subagents.
Or agent teams..

Subagents · Task tool

Main agent spawns N helpers. Each gets a prompt. Each runs in isolation. Each reports back. No cross-talk.

Best for: focused lookups, code search, structured reports. Lower token cost.

Agent Teams · Claude Code v2.1.32+

Independent Claude instances. Shared task list. Teammates message each other directly. Lead synthesizes.

Best for: parallel review, competing hypotheses, cross-layer refactors. Higher token cost.

# Subagents — main agent calls Task tool, gets summaries back.
# Agent Teams — flip the flag, then ask the lead to spawn a team.
$ export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1
$ claude
> Create a team of 3 reviewers for PR #142: security,
  performance, test coverage. Have them debate findings.

Subagents = MapReduce. Agent Teams = a small crew that argues. Same physics, different tokens. Docs: code.claude.com/docs/en/agent-teams.

Same repo, N filesystems. Merge later, in one place. No worktree, no parallel.

The dials · 04b  ·  cost as a knob

Three dials.
Or your $40 becomes $400..

Model split

Opus plans & reviews. Sonnet executes. ~5× cost gap, ~0× quality gap if the plan is good.

Context budget

/compact on long sessions. MEMORY.md for state worth keeping. New chat when the cache window slips past 5 minutes — token cost cliff, not a curve.

Token compression

caveman hook drops articles + filler. rtk trims tool schemas. ~30–60% off long sessions.

Cost is a knob, not a verdict. Tune the split, isolate the checkouts, compress the chatter — same output, fraction of the spend.

Where skills travel

Same markdown file runs on Claude Code, Cursor, Codex, Windsurf, Gemini CLI. The frontmatter is the index every agent reads; the body is the prompt every agent executes.

  • Same shape as Cursor rules, Codex AGENTS.md
  • Skill written for one CLI ships on all of them
  • Anthropic's catalog is anthropics/skills — MIT, fork-friendly

How you write one

Invoke skill-creator. Describe the trigger in plain English. Paste reference docs. Agent scaffolds the folder, fills the frontmatter, writes the body.

  • One prompt → committable skill in your repo
